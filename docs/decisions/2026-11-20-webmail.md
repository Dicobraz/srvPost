# 2026-11-20: веб-клиент — SPA поверх JMAP, без отдельного веб-сервиса

Решение по архитектуре веб-клиента (обсуждение 20.11; решения по скоупу/стеку приняты по рекомендации
агента без возражений владельца — при несогласии владелец правит этот ADR до старта mod-webmail-1).
Дизайн-эталон — DESIGN.md Postman (три-панель Outlook, Fluent-темы, без модалок, one-modifier хоткеи,
ru+en); мобильный паттерн — mobile Outlook (стек списка/чтения, нижняя навигация, свайпы, FAB).

## 1. Отдельного «веб-сервиса» нет: JMAP — и есть API веб-клиента

Сервер уже отдаёт всё, что нужно браузеру, тем же языком, что и Postman (crates/tp-jmap): Mail/Submission,
push по WebSocket (RFC 8887) и EventSource, блобы upload/download, FTS (Tantivy, ru/en, сниппеты),
Contacts/Calendars/GAL. Веб-версия — новый рендер поверх существующего API, не новый сервис.

Серверные добавки — три тонких вещи:

1. **Встраивание SPA в бинарь** под `/mail/` (rust-embed, строгий CSP, без CDN) — как веб-консоль
   (tp-admin/src/console.rs), выключается `modules.webmail.enabled=false`. Карго-фича `webmail`.
2. **Точка выпуска сессии — только запасной вариант.** В v1 вход = OIDC authorization code + PKCE
   прямо из SPA (как в веб-консоли, oidc-client-ts) → Bearer, который JMAP уже проверяет; fallback —
   Basic login + app-password. Отдельный endpoint «код → внутренний токен» (аналог admin-сессии)
   заводим лишь если IdP заказчика не даёт браузерного CORS/PKCE — упор оформить issue «решение».
3. **SAML 2.0 SP в tp-auth — после v1** (WEB-10): SRS ред. 8 привязывает SAML к веб-клиенту
   («без веб-интерфейса не используется»), но сервер уже умеет OIDC — в v1 хватит его.

## 2. Скоуп v1: почта + календарь (минимум) + контакты/GAL; задачи — следом

SRS даёт «почта, календари, контакты, задачи»; задачи частично не доделаны даже в Postman — уносятся
на следующую волну после v1. Календарь v1 — минимум: просмотр (день/неделя/месяц), приём/отказ от
встреч (метод веб-почты JMAP-50 готов, со спам-защитой), ответы iMIP через сервер, чтение free/busy.
Единые с десктопом механизмы сохраняются: спам — папка с ролью `junk` как единая правда (решение #134),
приём встреч — метод веб-почты (JMAP-50).

## 3. Стек и доставка

- **React 19 + TypeScript + Vite** — одна цепочка с веб-консолью: переиспользуются её композит CI-экшены
  (Node 26), бренд-токены из `design/tokens.toml` (virtual modules), react-router, vitest. Сборки —
  только в CI (правило 18.11: локально не собирать).
- Данные: TanStack Query поверх delta-sync JMAP (state-строки + `/changes`); live — WebSocket.
  Списки — TanStack Virtual (цель: 50 тыс. писем без лагов).
- Композер — TipTap (таблицы, вставка из Word — самая тяжёлая часть паритета с Postman).
- Чужой HTML — DOMPurify + sandboxed iframe; внешние картинки по умолчанию выключены (opt-in);
  предупреждения о подменённых ссылках — правила переносятся из DESIGN.md Postman.
- i18n — Fluent, переиспользуются `.ftl` каталоги Postman (ru/en).
- Офлайн/PWA — vite-plugin-pwa + Dexie (IndexedDB): кэш чтения, очередь исходящих с ретраями.

## 4. Мобильный — тот же SPA, PWA, паттерны mobile Outlook

Один код на десктоп и телефон: на узких экранах список и чтение стеком, нижняя навигация
Почта/Календарь/Контакты, FAB «Новое письмо», свайпы (удалить/архив/флаг), pull-to-refresh.
Манифест + service worker, устанавливается на телефон. Нативные приложения — не в планах v1
(SRS: «нативное приложение или PWA» — выбрано PWA).

## 5. Чаты — вне v1, шов в навигации закладывается сразу

Мессенджер решён отдельно (2026-11-17): homeserver Palpo, мобильный — Element X как есть, свой
брендированный веб-чат — после запуска, вместе с веб-клиентом. Тащить matrix-js-sdk с E2EE в
веб-почту v1 — раздувание скоупа. Навигация веб-клиента сразу проектируется с местом под раздел
«Каналы» (как в дереве Postman), чтобы вписать чат потом без переделки оболочки.

## 6. Риски (несутся в карточках волн)

1. Чужой HTML — главная поверхность атаки: санитайзер + песочница, картинки opt-in, ссылки
   с предупреждениями (WEB-03).
2. Редактор с таблицами и вставкой из Word (WEB-04).
3. Производительность больших ящиков: виртуализация + серверные окна JMAP (WEB-03).
4. Push при закрытой вкладке: в открытом окне WebSocket работает; «настоящий» Web Push — отдельный
   VAPID-шлюз на сервере, на iOS работает только у установленной PWA. За кадром v1; карточка — при
   появлении сценария.
5. Офлайн-отправка и конфликты; фоновой синхронизации в Safari нет (WEB-09).
6. Жизнь сессии: тихий renew между вкладками, «выйти везде» (WEB-02).
7. Паритет тем/плотностей с GPUI — ручной перенос по токенам консоли (WEB-01/03).

## Как применяется

- Полоса `mod-webmail` (модуль SRS 1.3 «Веб-клиент»); lanes.toml добавляется в mod-webmail-1
  (правка lanes.toml — класс B): `web/*`, `crates/tp-webmail/*`, `crates/thepost/src/webmail*.rs`
  (по образцу исключения admin в lanes.toml).
- Карточки WEB-01…WEB-10 — `docs/tasks/`, волны и зависимости — раздел полосы в `docs/PLAN.md`.
- Порядок: 01 → 02 → 03 → {04, 05, 06} → {07, 08, 09}; 10 (SAML) — после v1 по решению владельца.
- Приёмка волн — на стенде school-99 (beta): письмо из Postman видно в вебе и наоборот, спам и
  приём встреч синхронны между клиентами.
