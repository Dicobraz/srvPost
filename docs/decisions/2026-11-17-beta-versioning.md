# 2026-11-17. Нумерация бет — по образцу Postman: v<версия>-beta.N

Владелец: выровнять нумерацию бета-версий с Postman (репозиторий-образец; его правила — `docs/DEV.md` «Выпуск»
там: тег `v<версия>` ровно по версии, дефис в версии — предварительный выпуск, бета целит в будущий стабильный).

1. Тег ночной беты — `v<версия>-beta.N` вместо календарного `beta-YYYYMMDD`: бета целит в будущий стабильный
   выпуск `v<версия>` (семвер: 0.2.0 < 0.2.1-beta.1 < 0.2.1), N растёт с каждой бетой цели; повторы — следующий N.
2. Источник версии-цели — `appVersion` чарта (решение 111) и `version` Cargo, цикл 0.2.1. Отступление от образца:
   счётчик N живёт в git-тегах, а не в `version` Cargo — ночной бот не делает PR; бинарник рапортует цель (0.2.1).
3. Предохранитель: стабильный тег `v<версия>` уже существует — бета не собирается, поднять `appVersion`.
4. Стабильный выпуск: тег `v<appVersion>` руками на main после приёмки; `beta.yml` его не перезаписывает,
   `ci.yml` (release) собирает на тегах `v*`. Дефиса в версии нет — выпуск не pre-release (как в Postman).
5. Ночной ритм и пропуск при неизменном main — без изменений (CI-01); образ — те же три тега `<бета>`, `<версия>`,
   `beta` (решение 111). Теги `beta-YYYYMMDD` остаются историей, переходный учёт — обе схемы.
