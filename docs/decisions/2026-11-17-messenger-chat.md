# 2026-11-17: мессенджер — Palpo первым, идентичность через OIDC/LDAP

Решение владельца по итогам исследования `docs/research/2026-11-17-messenger.md` (PR #16). Подход — Matrix
(отчуждаемый продукт, отчуждаемая база); клиент Postman уже готов (CH-05) и сервероагностичен.

## 1. База homeserver — Palpo первым, Tuwunel запасным

Испытывать **Palpo** первым; если устраивает по чек-листу CH-05 (вход/SSO, sync, E2EE, файлы, поиск) и провижинингу
через admin API — Tuwunel не тестировать.

- Palpo: Apache-2.0, PostgreSQL 16+, MSC3861-делегирование, upstream OIDC/LDAP/JWT, retention, RTC-discovery (MSC4143),
  нативный слайдинг-синк (Element X работает), Complement 672/0/14. Риск: проекту 10 месяцев, комьюнити, без известных
  продакшн-деплоев.
- Synapse отпал: AGPL-3.0 несовместим с проприетарной лицензией продукта, Python.
- Tuwunel (Apache-2.0, полный день, RocksDB) — только при провале Palpo по существу: E2EE-клиентская совместимость,
  стабильность sync, бэкап PostgreSQL. Миграций между homeserver'ами нет — выбор окончательный.

## 2. Мост идентичности — OIDC заказчика, без OIDC — LDAP

«Одна учётка ThePost» = вход в чат без отдельного пароля. OIDC-провайдер будет у заказчика — свой не строить;
поддержать на обеих сторонах: клиент (Postman умеет SSO-вход через браузер) и сервер (у Palpo upstream OIDC
и MSC3861 есть). Развёртывание без OIDC у заказчика — LDAP (backend-ldap у Postman уже есть, у Palpo LDAP есть).
JWT-провижининг через tp-mxsync — не основной путь (вход не единый).

## Как применяется

- Bake-off Palpo на school-99 (стенд беты); чек-лист — CH-05 в `docs/research/2026-11-17-messenger.md`.
- Открытые вопросы (E2EE по умолчанию, федерация, мобильные и push) — issue с меткой «решение» у владельца.
- Планирование волн полосы chat — после решений по открытым вопросам.
