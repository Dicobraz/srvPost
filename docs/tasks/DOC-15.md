## Зачем
- Let's Encrypt проверяет управление доменом с нескольких независимых точек наблюдения (multi-perspective
  validation, MPIC; обязателен с 2025). Практическое следствие для установки: 80-й порт должен отвечать
  с **любого** адреса интернета — без гео-фильтров, «серых» пробросов и частичной DNS. Сейчас INSTALL
  говорит «порт 80 открыт, DNS имени указывает на ВМ» — этого мало: несимметричная видимость ломает выпуск
  молча, и администратор ищет причину в узле, а она на границе сети.
- Приёмка руками в тексте не описана: как отличить «всё хорошо» от «порт закрыт», не читая журнал узла.

## Сделать
- INSTALL, раздел `thepost_tls_mode: acme` (и PREREQUISITES, строка про 80-й порт): дополнить требование —
  80-й порт отвечает с каждого публичного адреса имени (все A/AAAA-записи ведут на этот узел), без
  гео-блокировок и выборочных пробросов; проверка выпуска идёт с нескольких точек мира, частичная видимость
  = отказ выпуска.
- Проверка руками: из внешней сети `curl -i http://<имя сервера>/` — ответ 404 это норма (у служебного HTTP
  только маршрут `/.well-known/acme-challenge/*`, остальное 404); недоступность/тайм-аут — сеть режет,
  выпуск не пройдёт.
- Ссылка на журнал узла при неудаче выпуска: первый запуск без сертификата не стартует, ошибка называет
  сервер ACME и адрес проверки (тексты узла уже такие — сослаться, не пересказывать).
