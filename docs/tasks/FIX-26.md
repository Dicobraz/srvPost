## Что случилось
Находка 20.11 на стенде Д.7 (school-99): расписание автообновления жило в crontab пользователя;
20.11 ~19:45 crontab оказался пуст (переписан) — стенд молча перестал проверять релизы, лог
оборвался на «актуально: v0.2.1-beta.4», бет 5–7 стенд не видел. Механизм не заметил собственной
смерти: узнали по отсутствию свежих строк в update.log. Попутно — curl писал прогресс-бары в лог.

## Сделать
- Расписание — systemd timer вместо crontab: `--install-timer` готовит пару юнитов
  `stand-update-<каталог стенда>.{service,timer}` (имя с каталогом — на хосте несколько стендов,
  юниты не должны затирать друг друга), календарь из того же `UPDATE_EVERY_DAYS`
  («17 4 */N * *» == «OnCalendar=*-*-*/N 04:17:00»), `Persistent=true` догоняет пропущенный
  запуск после простоя хоста. crontab (`--install-cron`) остаётся запасным вариантом без root.
- Итог каждого вызова — последняя строка «СТАТУС: ok|skip|fail» в журнале (ловушка на выход):
  живость расписания видна по свежести строк, исход — по последней; неожиданный выход (срыв
  `set -e`, обрыв) остаётся `fail`.
- Скачивание тарболла и sha256 — тихое (`curl -sS`): журнал — про исход, не про прогресс-бары.

## Приёмка
- На стенде (см. docs/manual-tests/FIX-26.md): timer установлен и виден в `list-timers`,
  ручной вызов пишет «СТАТУС: ok» последней строкой, занятой стенд — «СТАТУС: skip»,
  срыв установки — «СТАТУС: fail» и откат.
