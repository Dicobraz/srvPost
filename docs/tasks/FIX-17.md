# FIX-17 — fill-dav: соединение DAV на учётную запись (beta.3 привязывает сессию к соединению)

Место: `deploy/stand/roles/stand_generator/files/fill-dav.py`. Найдено 18.11 на beta.3 (podium):
`PROPFIND /dav/calendars/<юзер>/calendar/: 404` на учётках после первой — при том, что curl тех же
юзеров отвечает 207.

## Что случилось

fill-dav (потоки deliver) держит одно keep-alive HTTPS-соединение на поток и меняет учётные записи
запросами Basic на том же соединении. beta.3 привязывает DAV-сессию к соединению при первой
аутентификации (следствие конвейера/сессий) — последующие запросы других юзеров идут с правами первого,
чужое = 404 (concealment). Инструмент обязан не полагаться на поведение соединений.

## Сделать

- `Dav`: соединение на пару (логин, пароль) — ключ кэша соединений по логину; чужие соединения закрывать.
- Приёмка: `fill-dav.py` на чистом узле beta.3 проходит без 404 (50 учёток, state с нуля).
