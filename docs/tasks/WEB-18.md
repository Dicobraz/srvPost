# WEB-18. Сервер: push-токен по query — решение #292, вариант 1

**Класс:** B · **Волна:** `mod-webmail-18` (межполосный PR: jmap + docs) · **Ждёт:** `mod-webmail-12` (WEB-12 — та же полоса файлов tp-jmap, запуск строго после неё)

Решение владельца по [issue #292](https://github.com/Dicobraz/srvPost/issues/292): **вариант 1, Stalwart-путь** — query-параметр `access_token` на `/jmap/ws` и `/jmap/eventsource`, Bearer-токен, в логи не печатать. Снимает единственный серверный разрыв живого push веб-клиента (браузер не ставит заголовки на WS/EventSource; клиент с волны 3 уже передаёт `?access_token=`).

## Что делает

1. `tp-jmap/core/http.rs::authenticate` — на двух push-маршрутах (`/jmap/ws`, `/jmap/eventsource`) наряду с заголовком Authorization читать query-параметр `access_token` (только Bearer; Basic в query не принимается). Остальные маршруты — без изменений (заголовок только).
2. Логирование: токен/подпись запроса с токеном маскируется (не печатать значение; убедиться на месте, где логируются query).
3. Тесты: WS и EventSource с валидным токеном в query проходят; невалидный/чужой аккаунт — отказ как с заголовком; маршрут `/jmap/api` с токеном в query — отказ (заголовок-only); лог не содержит значения токена.
4. Клиент (уже готов, волна 3): push живой «за секунды»; приёмка «флаг/папка/прочтённость синхронны в обе стороны» — на стенде school-99.

## Приёмка

- Тесты выше зелёные; существующие push-тесты (заголовочный путь) не регрессируют.
- Ручная приёмка на стенде: письмо из Postman в открытой веб-вкладке — за секунды (не 30 с).
