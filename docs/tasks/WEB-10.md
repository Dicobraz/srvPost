# WEB-10. SAML 2.0 SP в tp-auth (после v1)

**Класс:** B · **Волна:** `mod-webmail-10` · **Ждёт:** `mod-webmail-2` (WEB-02), решение владельца об IdP заказчика

SRS ред. 8: SAML 2.0 поставляется вместе с веб-клиентом («без веб-интерфейса не используется»,
APP-B). В v1 вход — OIDC (решение 2026-11-20); SAML — следующая серверная волна, когда у
заказчика известен реальный IdP.

## Что делает

1. **SP в tp-auth:** метаданные (EntityDescriptor), ACS (POST-binding), единый logout
   (SLO, где IdP поддерживает), имя-политика (`NameID` → логин), часовые часы-skew,
   отклонение unsigned/повторных (replay) утверждений; конфиг `auth.saml` (IdP-метаданные,
   сертификаты, атрибут-маппинг).
2. **Выпуск сессии:** валидное утверждение → внутренняя сессия → Bearer, который JMAP
   принимает (аналог admin-сессии `POST /api/v1/session`, но для пользователей; здесь же
   запасной вариант обмена OIDC-кода из WEB-02, если он был заведён).
3. **Веб-клиент:** кнопка/автопереход входа через SAML (Web-SSO redirect), молчаливое
   обновление сессии через IdP-iframe, где возможно.
4. Аудит входов (успех/отказ) — как для OIDC.

## Приёмка

- Тест с shibboleth-совместимым IdP-стендом: вход в веб-клиент по SAML, JMAP-запросы
  с выданной сессией работают, logout закрывает сессию и на IdP (SLO).
- Replay/unsigned/просроченное утверждение — отказ, в аудите отказ.
- OIDC-вход (WEB-02) не регрессирует.
