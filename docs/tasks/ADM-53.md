# ADM-53. Правила журналирования — CRUD в Admin API + CLI (решение #171)

**Класс:** B · **Волна:** `admin-39` · **Ждёт:** `admin-38` (✅ #160, ADM-52), `meta-61` (✅ #115)

Решение владельца по issue #171: управление правилами журналирования (организация/
группа/ящик, направление In/Out/Both) из карточки UI-25 требует бэкенда — сейчас
правила задаёт только стендовый сценарий (psql) или их нет вовсе, экран консоли их
не рисует.

## Сделать

1. **Admin API**: CRUD правил журналирования поверх `PgJournal::rules`
   (схема `journal.rules`, META-88): список (по организации, с наследованием
   группа→ящик в порядке приоритета ящик > группа > организация), создать/изменить/
   удалить. Право — только роль администратора организации (не аудитор журнала:
   аудитор читает записи, правила — управление). Изменение подхватывается конвейером
   без перезапуска (порт `JournalRules` читает на каждое письмо — SMTP-53).
2. **CLI**: `thepost admin journal rule list/set/delete` (по образцу команд
   ADM-52 из #160: admin_cli.rs).
3. **Валидация**: адрес/домен/группа существуют, направление — enum, дубликаты
   (та же цель+направление) — отказ с подсказкой; аудит-журнал административных
   действий пишет изменение правил (кто/что/было-стало).
4. Приёмка-тесты: наследование приоритетов, право аудитора — 403 на запись,
   изменение видно новому письму без перезапуска (suite-уровень, MemJournal).

## Как делают другие
Mimecast/Exchange journal rules: цель (пользователь/группа/домен) + событие
(входящее/исходящее/оба) — та же модель.
