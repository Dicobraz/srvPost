# DEP-59 — автообновление стенда из релизов GitHub (stand-update.sh)

Место: `deploy/stand/stand-update.sh`, `deploy/stand/update.conf.example`, cron на хосте стенда.
Запрошено владельцем 2026-11-19: бету выкладывать в Releases, стенд должен обновляться сам.

## Задача

Каждый релиз-тарболл (`thepost-<тег>-x86_64-unknown-linux-gnu.tar.gz` + `.sha256`) должен попадать
на стенды без ручной перевозки через рабочий ноутбук. Обновление = **новая установка** (решение
2026-11-19: история миграций не хранится до релизов) — данные узла не переносятся, `fill-state.json`
сбрасывается, наполнение/прогон выполняются отдельно.

## Решение

Pull-модель: `stand-update.sh` на хосте-управлителе стенда (репозиторий публичный — скачивание без
токенов). По cron раз в 15 минут:

1. последняя версия — первая запись `tag_name` в `GET /releases` (pre-release включительно);
2. сверка с маркером `installed-version`; занятость стенда (ansible/прогон/fill) — пропуск;
3. скачать тарболл + `.sha256` в `inbox/`, проверить сумму, распаковать в `rel/<pkg>/`;
4. инвентарь (`thepost_binary_src`) — на новый путь;
5. пересоздать узел (`docker run` с `--ip` из `NODE_RUN_ARGS` — IP не уплывает, `stand_smb_address`
   и `/etc/hosts` генератора остаются валидными; последний переписывает роль install, FIX-11);
6. `--tags install,provision`; приёмка — md5 бинарника узла = тарболлу, юниты `thepost openbao
   postgresql` активны;
7. маркер, очистка старых версий (`KEEP`).

Самопочинка: при сбое установки маркер не обновляется — следующий вызов повторяет с чистого узла.
Lock-каталог от повторного входа. Режимы `--check` (exit 2 — есть новая) и `--tag <тег>`.

## Приёмка

- podium `~/thepost-perf` и school-99 `~/thepost-d7`: `--check` отвечает по маркеру; установка
  следующего тега проходит без ручных шагов (скачивание → чистая установка → приёмка зелёная);
- cron-записи на обоих хостах; повторный вызов поверх идущего — «пропуск».

## Политика обновления (решение владельца 19.11)

- **Интервал — одна настройка**: `UPDATE_EVERY_DAYS=3` в `update.conf`; cron стенда взводится из неё
  командой `stand-update.sh --install-cron` (раз в N дней, `17 4 */N * *`). Сменили интервал —
  повторили команду. Ручные `--check`/`--tag` — без ограничения.
- **Только безопасно**: простой стенда (busy-guard), sha256 тарболла, чистая установка, приёмка md5
  бинарника + служб; при провале приёмки — **откат на предыдущую версию** из `rel/` (маркер не меняется,
  узел остаётся рабочим), повтор при следующем вызове.
- **В проде по умолчанию выключено**: `AUTO_UPDATE=no` — умолчание скрипта; на тестовых/перф-стендах
  включается явно в `update.conf` (`AUTO_UPDATE=yes`).
