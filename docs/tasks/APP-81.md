## Зачем
- Сроки жизни сертификатов сокращаются (ballot SC-081v3: 200 дней с 03.2026, 100 с 03.2027, 47 с 03.2029;
  короткий профиль Let's Encrypt — 6 дней). При фиксированном `renew_before` (30 дней) короткий сертификат
  означает: узел ходит за сертификатом постоянно, и администратор, настроивший один раз, в 2027-м увидит
  «неожиданную» частоту продлений. doctor уже читает срок цепочек (проверки PKI) — место для подсказки есть.

## Сделать
- Проверка сертификата узла (`tls.cert_file`, тот же разбор `pem_certs`): срок жизни меньше `2 ×`
  эффективного окна продления (правило PLT-37: `min(renew_before, треть срока)`) — предупреждение с числами:
  «сертификат живёт N дней, продление начнётся через M дней после выпуска — частые обращения к серверу;
  ожидаемо при переходе CA на короткие сертификаты».
- `acme.enabled`: добавить к предупреждению «продлением занимается узел (встроенный ACME)»;
  выключен — «автоматическое продление не настроено: перевыпуск — вручную или внешним средством».
- Тон не «ошибка»: короткий сертификат — норма нового графика CA; предупреждение — о смене режима обслуживания.

## Приёмка
- Тест: сертификат на 47 дней — предупреждение с числами; на 398 дней — нет.
- Тест: `acme.enabled` — подсказка про встроенный ACME; без секции — про ручной перевыпуск.
- Тест: файл сертификата не читается — прежнее поведение doctor (ошибка проверки), без паники.
