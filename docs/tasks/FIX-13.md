## Что случило прогон

1. **Исходящая нагрузка — 100 % отказов 550** (276 отказов, зонд доставки n=0, индексация «не найдено 55»):
   `outgoing()` шлёт корпус fill'а (`From: sender<n>@external.test`, make-corpus.py:51) через swaks c AUTH
   `user<n>@stand.test` → узел корректно отвергает чужой From («отправить только со своего адреса», SRS).
   Продукт прав — инструмент врал.
2. **Сэмплер узла умирал мгновенно, тихо**: файлы стенда в tarболле, собранном из виндового чекаута, — с CRLF;
   shebang `#!/usr/bin/env python3\r` → `env: python3\r: No such file or directory`. Задача async/poll=0 —
   никто не заметил; критерии 6/7/14/17 Д.7 остались «не измерялось» (нет smb-samples.csv). Остальные CRLF-файлы
   выживали (python3-запуск и node/k6 толерантны), в git — LF: ломается только при сборке тарболла из рабочей
   копии Windows без .gitattributes-принуждения.
3. Прочее из прогона: 421×55 на входящей (причина не в журнале узла — воспроизвести после фикса), JMAP query
   p95 311 мс и SELECT 10k p95 939 мс при тихом хосте — честный сигнал продукта, не стенд (пороги 200/100 мс).
