# WEB-03. Список и чтение: ящик, потоки, санитайзер, живой push

**Класс:** A · **Волна:** `mod-webmail-3` · **Ждёт:** `mod-webmail-2` (WEB-02)

Ядро веб-почты. Дизайн — DESIGN.md Postman: три-панель (папки | список | чтение), команды
без модалок, тосты с Undo; на мобильном (WEB-08) стек.

## Что делает

1. **Данные:** JMAP session → Mailbox/get (дерево, роли, `role:"junk"` для «Спама»),
   Email/query окнами (позиция + лимит), delta-sync (`Email/changes` по state-строкам),
   push — WebSocket RFC 8887 (`/jmap/ws`), при недоступности — EventSource.
   Состояние — TanStack Query; нормализация id, дозагрузка окон при скролле.
2. **Список:** TanStack Virtual (цель — 50 тыс. строк без лагов), потоки (thread-группировка,
   три вида отображения как в Postman: лента без цитат / стек / «как в Outlook»), флаги и
   категории (keywords, клавиши 1–9), quick filters, непрочитанность, вложенность-иконка.
3. **Папки:** дерево, перенос (drag-drop + контекстное меню + клавиши), архив, «Спам» —
   единая правда (решение #134): кнопки «Не спам» / «Пожаловаться» = перенос письма в/из
   папки роли junk, отдельного API нет.
4. **Чтение HTML — hostile input:** DOMPurify + sandboxed iframe (CSS изолирован), внешние
   картинки по умолчанию выключены (opt-in на письмо/на отправителя, как в Postman),
   подменённые/внешние ссылки — предупреждение перед переходом. Текстовая часть — как fallback.
5. **Хоткеи:** one-modifier схема из DESIGN.md (Ctrl+буква/цифра = команда, голые клавиши —
   навигация), таблица клавиш — из PARITY.md, раскладка RU/EN не мешает.

## Приёмка

- Письмо, отправленное из Postman, появляется в вебе живым (WS) за секунды; флаг/папка/
  прочтённость синхронны в обе стороны.
- Перекладывание в «Спам» в вебе меняет папку для Postman и наоборот (единый механизм #134).
- Письмо с трекинг-пикселем не грузит внешние картинки до явного разрешения; spoofed-link
  показывает предупреждение.
- 50 тыс. писем в папке: скролл 60 fps (профиль в комментариях PR), delta-sync не перечитывает
  всё окно.
