# WEB-20. Сервер: keywords делегатом на общий accountId

**Класс:** B · **Волна:** `mod-webmail-20` (межполосный PR: jmap + docs) · **Ждёт:** `mod-webmail-15` (выявила разрыв), `mod-webmail-18` (очередь tp-jmap)

Разрыв, найденный волной 15: «Взять в работу» (S5-28 Postman, формат `pm.taken…`) на общем
ящике не работает — делегату сервер отвечает `accountNotFound` на `Email/set` по чужому
accountId (`crates/tp-jmap/src/delegate.rs`, JMAP-49: делегату отдаются только
`Email/query`/`queryChanges`/`get`). Клиент веба (WEB-15) корректно шлёт патч по accountId
владельца и показывает честную ошибку — без этой серверной волны «Взять в работу» в вебе
не завершится.

## Что делает

1. Разрешить делегату с правом записи (`l`/`rw` по ACL RFC 4314 — сверить с Postman-смыслом
   «взять в работу») **ограниченный Email/set на чужом accountId**: только обновление keywords
   (`pm.taken*` и стандартные ключи), без create/destroy/смена папок. Выбор механики — по коду
   (расширить `check_account` для keywords-патча или отдельный метод `vnd.thepost` — решение
   агента по кодовой базе, аргументировать в PR).
2. Аудит/лог: изменение «взял/вернул» делегатом — событие как у остальных действий.
3. Тесты: делегат с правом — патч keywords проходит (round-trip); без права — отказ;
   create/destroy у делегата по-прежнему запрещены; лимит сессий/адмиссия не регрессируют.

## Приёмка

- «Взять в работу» в вебе и в Postman на общем ящике: оба видят «Взято: …» синхронно (после
  мержа — ручная приёмка на school-99).
- Без права записи у делегата — отказ, календарных/папочных изменений нет.
