# META-90 — GAL: инкрементальный признак версии книги (gal_version)

Место: метаданные GAL (контрольная сумма книги). Источник — issue #6 (slow-лог беты
`beta-20261114.4`, school-99, 50 ящиков: `SELECT md5(string_agg(…))` по всем учёткам
тенанта — 1.227 с на цикл `maintenance.gal_interval`). Вердикт владельца 20.11 —
подход «`gal_version` триггером».

## Что случилось

Каждый цикл GAL агрегирует все `accounts` + `org_attributes` тенанта ради md5-признака
«книга изменилась». На 50 ящиках под нагрузкой — 1.2 с (порог slow-лога 1 с); на
enterprise (тысячи учёток) — линейный рост на каждый цикл.

## Сделать

- Таблицам `accounts`/`org_attributes` — триггер, обновляющий monotonically
  increasing `gal_version` тенанта (или отдельной таблицы версий) при любом
  изменении строк книги.
- Контроль книги — сравнение сохранённой и текущей версии (одна скалярная
  величина), пересборка книги только при изменении; реакция на недоступность СУБД
  — прежняя («книга GAL не обновлена: повтор через maintenance.gal_interval»).
- Начальная миграция (следующий номер после 0003) заполняет версии тенантов.

## Приёмка

- Тест: изменение учётки/орг-атрибута поднимает версию, контроль ловит, книга
  пересобирается; без изменений — скана нет.
- Slow-лог на стенде Д.7: строки `string_agg`-скана исчезают.
