## Сделать
- Эталонная конфигурация Enterprise: бакет журнала на SeaweedFS с Object Lock (режим governance по умолчанию, compliance — явно), отдельный от BLOB ящиков; пресеты Ansible/Helm дополняют переменные журнала (по образцу существующих ролей).
- Профиль SMB: каталог журнала на локальном диске, права только на добавление; проверка предупреждения doctor на стенде.
- Стендовая проверка (Д.6/бета): включить правило журналирования Both на организацию — входящие и исходящие записи; выгрузка .eml с конвертом; `restore_index` после очистки индекса — поиск восстанавливается; `verify chain` после намеренной порчи — разрыв обнаруживается; замер задержки конвейера с журналированием и без (риск 22) — в отчёт стенда.
- Обновить чек-лист приёмки беты (checkN.py) шагом «журнал: запись, поиск, выгрузка, восстановление» — по решению владельца о включении в приёмку.

## Как делают другие
- Облачные почтовые архивы (Mimecast и др.): отдельный immutable-бакет под журнал — та же схема.

## Приёмка
- Прогон на стенде: правило Both пишет обе записи; восстановление индекса из бакета работает; порча записи обнаруживается; задержка с журналированием измерена и записана в отчёт; SMB-профиль показывает предупреждение doctor.
