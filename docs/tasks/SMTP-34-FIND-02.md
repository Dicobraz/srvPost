# FIND-02 → smtp-34 — 421 max_connections при стенде Д.7: лимит или порог (Д.7 №3)

Место: `crates/tp-smtp/` (лимит соединений), эталон SMB (настройка). Прогон beta.3 на эталоне Д.2
(20261118T192030Z): **421 × 267** при 200 простаивающих IDLE + нагрузка; SMTP 250 p95 = 697 мс
(без отказов — по нити приёма быстро, отказы ломают p95 и сборку).

## Что известно

Причины 421 теперь в журнале (FIND-01, PR #64) — при следующем прогоне видно, какой лимит срабатывает
(max_connections / rate_limit_ip). На стенде 200 IDLE + 30 imap + push — для 50 пользователей это
пиковый час по модели Д.3, лимит соединений SMB-эталона может быть просто меньше пиковой нагрузки.

## Сделать

- Из журнала beta.4-прогона: какая причина 421 (поле reason).
- Решение (владельцу, issue «решение»): поднять max_connections в эталоне SMB до пикового профиля Д.3
  (обосновать числом) или признать поведение нормой и перевести критерий №3 на «без отказов при
  номинальной нагрузке» — уточнить формулировку Д.7.
- Приёмка: прогон Д.7 без 421 при номинальной нагрузке; SMTP 250 p95 < 500 мс.

Волна: smtp-34 (класс A после решения; до него — только сбор фактов прогоном).
