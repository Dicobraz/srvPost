# PERF-07 — JMAP Email/query на уникальных фильтрах: 447 мс при пороге 200 мс (Д.7 №1)

Место: `crates/tp-jmap/` (Email/query, некэшируемый путь), остаток после PERF-02 (jmap-32, кэш списков).
Прогон beta.3 на эталоне Д.2 — 20261118T192030Z (4 vCPU/8G): **p95 447 мс**, get 340 мс.

## Что известно

Кэш jmap-32 не помогает зондам: их фильтры уникальны (случайные слова), попаданий в кэш запросов нет —
замерян «холодный» путь. 447 мс — это стоимость самого поиска: SQL по журналу/таблицам писем с фильтром
по тексту и сортировкой, плюс сборка ответа.

## Сделать

- Профилировать холодный Email/query (EXPLAIN на ящике big 10k): фильтр по тексту (LIKE?), сортировка,
  число строк. Доминанта, скорее всего, текстовый предикат по телам.
- Кандидаты: индекс под типовые фильтры (received_at DESC — покрывающий для сортировки), перенос
  текстового предиката в FTS-индекс вместо LIKE (уже есть tp-search!), пагинация без полной выдачи.
- Приёмка: Д.7 №1 p95 < 200 мс на эталоне Д.2 (podium), замер — критерием Д.7.

Волна: jmap-34 (класс A). База — `docs/manual-tests/DEP-13.md`, «Прогон 2026-11-18».
