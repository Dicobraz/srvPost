# PERF-08 — IMAP SELECT 10k: 108 мс, порог 100 мс — добить кэшем/прогревом (Д.7 №2)

Место: `crates/tp-mailstore/` (CachedMessages, PR #51) + замер. Прогон beta.3 на эталоне Д.2
(20261118T192030Z): **p95 108 мс** — в 12 раз лучше beta.2 (1.26 с), до порога 8 мс.

## Что известно

Кэш списков работает (сравнение с beta.2), но p95 ловит первый SELECT после инвалидации (fill шлёт
письма в течение прогона → журнал папки меняется → кэш перестраивается). 10000-й ящик big постоянно
получает новые письма — его кэш почти всегда холодный.

## Сделать

- Замерить раздельно: холодный SELECT (после доставки) и тёплый (из кэша). Если тёплый << 100 мс —
  путь верный, вопрос в инвалидации.
- Смягчить перестройку: инкрементальный патч кэша по журналу (механизм patch_max уже есть — проверить,
  что для SELECT-пути он применяется, а не только для JMAP), приоритет перестройки big.
- Приёмка: Д.7 №2 p95 < 100 мс на эталоне Д.2 при включённой fill-нагрузке.

Волна: mailstore-20 (класс A). Связано: [[PERF-01]], база — прогон 20261118T192030Z.
