# PERF-01 — IMAP SELECT папки 10 тыс. писем: p95 944 мс при пороге 100 мс (Д.7 №2)

Место: `crates/tp-mailstore/` (SELECT/статистика папки), найдено прогоном Д.7 2026-11-17.

## База

| Прогон | Стенд | p95 |
|---|---|---|
| 20261117T174936Z-speed-base | school-99 (8 vCPU, sync_commit=off) | **939 мс** |
| 20261117T182831Z-speed-base | school-99, тише | **944 мс** |
| 20261117T202158Z-speed-base | podium-dev (2 vCPU/3.8G, честный конфиг) | **2.68 с** |

Порог Д.7 №2 — **< 100 мс** (SELECT папки 10 тыс. писем). Отказов нет — путь корректный, но медленный.
Стабильность school-99 цифр (939/944) — не шум: воспроизводимый путь (запрос счётчиков/ unseen по 10k
строк на каждый SELECT?). Пул СУБД ждёт (max 25–64 ожидающих, среднее 3–144 мс) — SELECT, вероятно,
держит соединение и загружает строки.

## Сделать

- Разобрать путь SELECT: какие запросы СУБД и сколько строк читается; EXPLAIN на ящике big.
- Цель: счётчики и флаги папки — агрегатами (COUNT/индексы), без полной выгрузки; повторный SELECT
  того же ящика — из кэша с инвалидацией по версии папки.
- Приёмка: Д.7 №2 p95 < 100 мс на стенде эталона Д.2 (4 vCPU/8 GB), без регрессии критерия №5.

Волна: mailstore-16 (класс A). Связано: [[PERF-02]] (тот же профиль нагрузки), база прогона —
`docs/manual-tests/DEP-13.md`, «Прогон 2026-11-17».
