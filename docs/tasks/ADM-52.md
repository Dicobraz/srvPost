## Сделать
- Роль `journal-auditor` в ролевой модели Admin API (вход только OIDC, как прочие роли администраторов): поиск по журналу (`JournalQuery`: отправитель, получатель, Message-ID, интервал, правило), просмотр записи, выгрузка `.eml` с конвертом. Роли `administrator` организации/инсталляции содержимое журнала недоступно; пользовательскому токену — нет (SRS 4.9, 5.2); через IMAP и JMAP журнал не виден.
- Каждое обращение к журналу (поиск, просмотр, выгрузка) записывается в журнал аудита: кто, что, когда, критерий запроса.
- `verify_chain` через Admin API — отчёт целостности цепочки (для аудита и doctor).
- Выгрузка во внешний архив заказчика: по настройке — каждая новая запись журнала дополнительно выгружается (.eml с конвертом) внешнему получателю (каталог/HTTPS-эндпоинт задаётся конфигурацией); сбой выгрузки не влияет на доставку почты, повтор по журналу выгрузки.
- OpenAPI-спецификация дополнена, CLI `thepost admin journal …` (search/get/export/verify) генерируется из неё; консоль — UI-25.

## Как делают другие
- Exchange: Journaling Archive → внешний архив (например, на СЭД/спец. системы РФ — InfoWatch Traffic Monitor, SearchInform); eDiscovery-поиск администратором комплаенса, не почтовым админом (https://learn.microsoft.com/en-us/purview/ediscovery).

## Приёмка
- Тесты ролей: `journal-auditor` ищет и выгружает; `administrator` и пользовательский токен — 403; каждое обращение в журнале аудита; `verify` возвращает отчёт; выгрузка во внешний архив по настройке воспроизводима после сбоя.
