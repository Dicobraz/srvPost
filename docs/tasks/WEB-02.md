# WEB-02. Вход: OIDC PKCE из SPA + app-password, жизнь сессии

**Класс:** B · **Волна:** `mod-webmail-2` · **Ждёт:** `mod-webmail-1` (WEB-01)

Вход без новой серверной точки (решение 2026-11-20): SPA берёт токен сама, JMAP уже
проверяет Bearer OIDC и Basic app-password (tp-jmap/core/http.rs).

## Что делает

1. **OIDC authorization code + PKCE** через `oidc-client-ts` — как в веб-консоли: редирект на
   IdP, silent renew, `Bearer` в JMAP. Конфиг — `modules.webmail` в toml (discovery-URL IdP,
   `client_id`, scope) — дополнение конфиг-схемы (класс B).
2. **Fallback: Basic login + app-password** (форма входа, пароль не хранится дольше сессии).
3. **Жизнь сессии:** тихий renew между вкладками (BroadcastChannel/StorageEvent — одна вкладка
   renew'ит, остальные подхватывают), logout (в т.ч. «выйти везде» — revoke app-password
   там, где IdP даёт end-session), обработка истёкшего токена (перевход без потери черновика).
4. **Запасной вариант** (не в этой волне): если IdP заказчика не отдаёт браузерный CORS/PKCE —
   серверная точка «код → внутренний Bearer» (аналог admin-сессии). Упор на это — issue
   с меткой «решение», не локальная самодеятельность.

## Приёмка

- Стенд school-99: вход через OIDC → `GET /jmap/session` отвечает; перезагрузка страницы
  не разлогинивает; истёкший токен → тихий renew.
- Вторая вкладка подхватывает новую сессию, «выйти везде» закрывает обе.
- Вход по app-password работает; неверный — понятная ошибка, без блокировки (abuse-гвардия
  сервера не срабатывает на одну опечатку).
