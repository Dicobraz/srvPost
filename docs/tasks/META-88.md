## Сделать
- Миграция `0045_journal.sql`: схема `journal` — таблица записей индекса (id, организация, отправитель, получатели, message_id, время, правило, ссылка на запись хранилища, hash, prev_hash) и таблица правил журналирования (`JournalRule`: область, цель, направление, состояние) — данные организации; поиск по отправителю, получателю, Message-ID, интервалу и правилу — индексы под запрос `JournalQuery`.
- Хеш-цепочка: `hash = H(prev_hash ‖ canonical(record))` в порядке записи; `verify_chain() -> ChainReport` — разрыв цепи с номером записи; запись и изменение индекса — только добавление (как журнал аудита, SRS 3.1).
- `PgJournal` — реализация `JournalStore` (CTR-97) по индексу: `append` (в той же транзакции, что и запись хранилища записей — через контракт двухфазно: сначала запись в бакет, затем индекс; при обрыве индекс чинится `restore_index`), `search`, `export` (ссылка на запись), `restore_index()` — полное восстановление индекса из хранилища записей (перечитывает записи, пересобирает цепочку).
- Тесты на PostgreSQL (как pg-наборы tp-testkit): цепочка рвётся при подмене — `verify_chain` ловит; `restore_index` после пустого индекса восстанавливает поиск; правила в организации и группах.

## Как делают другие
- Индекс с хеш-цепочкой — сертификатная прозрачность RFC 6962 (Merkle/chain) и journal-хранилища типа append-only log; отличие — цепь хешей записей журнала переписки для eDiscovery-доказательности.

## Приёмка
- `suite::journal` (CTR-97) проходит на `PgJournal`; тест подмены и восстановления зелёные; миграция вперёд/назад без потерь.
