## Сделать
- Доставка (приём smtp-in, submission/JMAP EmailSubmission, доставка в ящик) переводится на реестр этапов CTR-96: этапы ядра — проверки сессии (MAIL, RCPT), Milter, журналирование (SMTP-53), Sieve ящика, итоговый контроль, доставка или постановка в очередь; порядок и точки фиксированы контрактом.
- Отказы по стадиям: условия на MAIL/RCPT — по конверту, отказ отдельному получателю; на DATA — по содержимому, отказ всему письму; входящая почта обрабатывается до доставки, исходящая — до очереди. Существующие проверки (экран соединений, лимиты, Milter, модерация) занимают свои точки без изменения поведения.
- Итоговый контроль действий: после всех этапов проверять `ActionSet` (перенаправления из Sieve и правил, копии, адресаты) по `OrgPolicy`; в базе — `forbid_external_forward` (по умолчанию выключен): запрет внешней пересылки перехватывает redirect из скрипта ящика; нарушение — отказ с понятной причиной в журнал доставки.
- Точки регистрации модульных этапов (SRS 2.5) доступны для будущего модуля «Правила потока почты» (SRS 4.10): before/after вокруг Sieve ящика — задел, без реализации модуля.
- Тесты: порядок этапов соответствует контракту; отказ на RCPT — одному получателю; `forbid_external_forward` отклоняет redirect наружу из скрипта ящика и пересылку копии наружу; без политики поведение прежнее.

## Как делают других
- Postfix: cleanup/queue manager — фиксированный конвейер, фильтры подключаются в заданных точках (header_checks, milter) — аналог реестра с фиксированными точками ядра.

## Приёмка
- Регресс существующих тестов доставки без изменений поведения (политики выключены); новые тесты реестра и итогового контроля зелёные; интеграционный сценарий «redirect наружу при запрете — отказ, запись в журнал доставки с причиной».
