## Сделать (решение владельца 19.11, issue #112)
- Спам определяется максимально рано — на приёме (`tp-smtp`), и **ни один автоматический
  механизм его не обрабатывает**: автоответы (уже пропускаются), действия Sieve
  (`processcalendar` — уже гасится вызывающим в SMTP-50; проверить остальные действия на
  письме с вердиктом спам), генерация DSN/уведомлений (уже без DSN чужому отправителю),
  любые будущие автоматические реакции — гасятся на вердикте.
- **Ручное принятие встречи из спам-письма запрещено**: iTIP-обработка (accept/tentative/
  decline/counter) для письма, классифицированного спамом или лежащего в папке «Спам»,
  отклоняется сервером — приглашение не вносится в календарь, клиент получает отказ.
  Вердикт/папка проверяются в точке приёма iTIP-запроса.
- Письмо со спам-вердиктом попадает в папку «Спам» — и всё: никакой другой обработки.

## Как делают другие
- Gmail: спам не проходит фильтры пользователя и не вызывает автоответы
  (https://support.google.com/mail/answer/900109).
- Exchange transport rules / anti-spam stamps: спам-письмо исключается из правил потока
  почты и отчётных механизмов (https://learn.microsoft.com/en-us/defender-office-365/anti-spam-protection-about).
- RFC 9671 §5: календарные данные спам-письма не обрабатываются
  (https://www.rfc-editor.org/rfc/rfc9671#section-5).
- Отличие: запрет распространён и на ручной iTIP из спам-письма — сервер отклоняет
  обработку, а не только клиенты скрывают кнопку.

## Приёмка
- Тест: письмо со спам-вердиктом — автоответ не генерируется, Sieve-действия (включая
  `processcalendar`) не применяются, DSN/уведомления нет.
- Тест: iTIP-обработка (accept) письма со спам-вердиктом / из папки «Спам» — отклоняется,
  календарь не меняется; то же письмо после переноса из «Спама» — обрабатывается.
