# WEB-09. Офлайн: кэш чтения и очередь исходящих

**Класс:** A · **Волна:** `mod-webmail-9` · **Ждёт:** `mod-webmail-4` (WEB-04)

Границы честно фиксируем: фоновая синхронизация в Safari нет; офлайн — это чтение кэша
и отложенная отправка при открытом приложении (решение 2026-11-20, риск №5).

## Что делает

1. **Кэш чтения:** IndexedDB (Dexie) — последние папки/письма (метаданные + тело прочитанных),
   лимит объёма и LRU-вытеснение; чтение офлайн из кэша, пометка «офлайн».
2. **Реконсиляция:** при появлении сети — delta-sync по state-строкам (дозагрузка изменений,
   не перечитывание); конфликт правок флагов — последний писатель с серверной версией
   (JMAP state не даёт тиражировать расхождение молча).
3. **Очередь исходящих:** отправка офлайн — черновик в очереди (IndexedDB), ретраи с
   экспоненциальной паузой при появлении сети, отмена пользователем; после успешного
   EmailSubmission письмо уходит в «Отправленные» сервера (без дублей при повторе).
4. **Индикация:** честный индикатор офлайна/отложенных, счётчик очереди.

## Приёмка

- Airplane mode: прочитанные письма открываются из кэша; композиция и «отправить» — письмо
  уходит автоматически после включения сети, в «Отправленных» одна копия, дубли не тиражируются.
- Реконсиляция после офлайна приносит только изменения (счётчик запросов в логе), полный
  перечитывания нет.
- Safari (iOS): нет фоновой отправки — очередь дожидается открытого приложения, приёмка это
  документирует как ограничение.
