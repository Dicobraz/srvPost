# META-89 — ОТКЛОНЕНО владельцем 19.11: история миграций не хранится

Место: `crates/tp-meta/` (резолвер миграций). Найдено 18.11 на podium: узел beta.2 → бинарник beta.3
не стартует: «migration 2 was previously applied but is missing in the resolved migrations».

## Что случилось

META-71 (PR #74) свернул миграции 0001…0044 в базовую схему 1.0 (запись в `_sqlx_migrations` заменена
одной). База, обновлённая до beta.2 (миграции применены по одной), при старте beta.3 видит в своей
`_sqlx_migrations` записи, которых нет в резолвере, и падает. Правило бет «только новая установка»
спасает стенды, но любое развёртывание следующего релиза поверх существующего узла упрётся в это.

## Сделать

- Резолвер миграций: записи о версиях, отсутствующих в текущем списке, — не ошибка, если версия ниже
  базовой схемы (пометить «свёрнута», записать свернувшую запись в схему миграций узла — один алиас).
- Приёмка: узел beta.2 → бинарник 1.0 стартует без сноса базы (тест: накатить старую схему, подменить
  бинарник, проверить старт и отсутствие потери данных).

Волна: meta-89 (класс B — миграции/схема). Связано: META-71 (PR #74).

**Решение владельца (19.11):** до релизов история миграций не хранится вообще — каждая версия работает
только со своей базой, обновление на новую версию = новая установка. Миграционная совместимость будет
писаться на уровне релизов (когда появится первый релиз и миграции 1.0 → 1.x). PR #100 закрыт.
